# 包裹地圖

這一頁說明包裹裡每個資料夾放什麼、給哪個工具用。版本號只寫在 `VERSION` 這個檔案裡（目前是 `1.0`），其他地方要用版本號都從這裡取。

## 資料夾一覽

| 資料夾或檔案 | 放什麼 | 哪些工具會用到 |
|---|---|---|
| `VERSION` | 版本號，只有一行（例如 `1.0`） | 打包時取用；人不用改 |
| `更新紀錄.md` | 每一版改了什麼、要不要重裝 | 給人看 |
| `說明書/` | 三份說明書：安裝、第一次使用、日常速查 | 給人看 |
| `外掛/` | 外掛的總目錄（叫「marketplace」）。安裝時指向這個資料夾 | Claude Code、Codex |
| `外掛/dev-bingfa/skills/` | 固定流程用的 skill（含 `commit`） | Claude Code、Codex 都會載入 |
| `外掛/dev-bingfa/agents/` | 三個助手設定（Claude Code 格式） | 只有 Claude Code；Codex 不會讀這裡 |
| `外掛/dev-bingfa/web-search-modules/` | 網路搜尋助手要讀的 5 份搜尋策略（跟著主外掛一起裝） | Claude Code、Codex 的網路搜尋助手 |
| `外掛/dev-bingfa-check/` | **選用**外掛：存檔時自動檢查的 Python 腳本，加上找 Python 的小程式（`run.sh`、`run.cmd`、Codex 在 Windows 用的 `codex-post.cmd`）和分辨兩種工具輸入的 `post_check.py`。電腦沒有 Python 就不要裝，這項就是「沒啟用」 | Claude Code；Codex 未實測成功 |
| `codex/agents/` | 三個助手設定的 Codex 版本（TOML 檔），安裝時手動複製到 `~/.codex/agents/` | 只有 Codex |
| `規則/` | 通用規則（同一份內容存成 `CLAUDE.md` 與 `AGENTS.md`）、Claude 專用附錄、Codex 專用附錄、個人偏好範例 | 通用規則：所有工具；`CLAUDE專用附錄.md`：只有 Claude Code；`CODEX專用附錄.md`：只有 Codex |
| `基本版/` | 直接複製就能用的 `.agents/skills/` 和 `AGENTS.md` | Cursor、Antigravity 等（未實測） |
| `離線副本/` | Matt Pocock 工具的離線副本與原作者授權聲明。連不上 GitHub 時才用 | 所有工具（備案） |

## 兩個重點

- **外掛不能帶規則檔**：Claude Code 和 Codex 的外掛都不會讀裡面的 `CLAUDE.md` / `AGENTS.md`，所以規則放在 `規則/`，說明書教人手動放。
- **安裝前先把包裹解壓到固定位置，裝完就不能搬動、改名或刪掉這個資料夾**：外掛是用資料夾路徑登記的，Claude Code 每次都直接讀這個資料夾。搬走或改名後，Claude Code 會馬上載入失敗（實測看到 `failed to load: cache-miss`，兩個外掛都不能用；改回原名就恢復）。Codex 上搬動的後果未實測。

## 將來把某個工具從基本版升級成完整版，要加在哪裡

以「替 Cursor 補完整版」為例，只要在下面這些位置加東西，其他資料夾不用動：

1. **助手設定**：在包裹最上層新增一個以工具命名的資料夾（例如 `cursor/agents/`），寫法比照 `codex/agents/`。
2. **自動檢查**：如果該工具能讀 Claude Code 格式的外掛，直接沿用 `外掛/dev-bingfa-check/`；不能的話，在 `cursor/` 底下另外放它自己的設定。
3. **說明書**：在 `說明書/` 的安裝說明裡加一章。
4. **基本版**：該工具升級後，把它從 `基本版/` 的適用清單拿掉。

`外掛/dev-bingfa/skills/` 和 `規則/` 是所有工具共用的，升級時不需要複製一份。
