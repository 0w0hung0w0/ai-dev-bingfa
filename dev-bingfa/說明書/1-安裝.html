0　開始之前

這包是什麼

「AI 系統開發兵法」是一套固定的 AI 開發流程。裝好之後，你的 AI 工具會照同一套順序做事：先問清楚需求 → 寫規格 → 切成小任務 → 先寫測試再寫程式 → 找「另一雙眼睛」審查 → 交付並檢討。不管是誰、用哪個 AI 工具，品質都比較穩定。

安裝的方法很簡單：你把壓縮檔解開，然後對 AI 說一句話，請它讀包裹裡的「安裝指示」檔照著做。AI 會自己一步一步裝好，最後給你一張結果表。

裝好之後你會得到什麼

  • Matt Pocock 的流程工具：一組公開的 AI 技能（skill，意思是「寫好的一套做事步驟」，AI 照著做），負責主線的每一步，例如追問需求的 grill-me、寫規格的 to-spec。
  • 本包裹的 4 個技能：brownfield-recon（接手不熟的專案前先畫地圖）、blast-radius（查改的東西有沒有弄壞別人）、seam-audit（查不同零件之間的約定有沒有人守）、commit（幫你把改動存成一個版本）。
  • 3 個助手：另一個 AI 分頭做事，負責大量讀資料、照計畫實作、上網查資料。主對話負責規劃和把關。
  • 規則：一份「AI 該怎麼做事」的規則，會加到你電腦上 AI 每次都會讀的規則檔尾端。
  • 存檔自動檢查（選用）：AI 每寫完一個 Python 程式檔，電腦就自動掃一次一種常見錯誤。只有 Claude 版、而且電腦有 Python 才會裝。

1　解壓縮到固定的資料夾

1-1　把壓縮檔整個解開

要做什麼在壓縮檔上按右鍵，選「解壓縮全部」。跳出的視窗裡有一格「解壓縮到這個資料夾」的路徑（畫面可能略有不同），把它改成一個以後不會搬動的資料夾，建議：
C:\dev-bingfa-1.0

建議用英文、沒有空白的路徑（中文和空白在測試裡也能用，但英文最保險）。不要直接在壓縮檔裡面點開檔案來用，也不要放在「下載」或暫存資料夾。

看到這個代表成功打開 C:\dev-bingfa-1.0，裡面直接看得到 安裝指示-ClaudeCode.md、安裝指示-Codex.md、VERSION、外掛、規則、離線副本、說明書 這些東西。
沒看到的話如果打開後只看到一個同名的資料夾（例如變成 C:\dev-bingfa-1.0\dev-bingfa-1.0），或你解到別的名字的資料夾，都沒關係：以真的看得到 安裝指示-ClaudeCode.md 的那一層當包裹資料夾，後面句子裡的路徑換成那一層（例如 C:\dev-bingfa-1.0\dev-bingfa-1.0\安裝指示-ClaudeCode.md）。決定好之後就不要再搬動。
重要：裝好之後，這個資料夾不能搬動、不能改名、不能刪除。
Claude 版是直接讀這個資料夾裡的東西。測試時把資料夾改名，Claude 馬上載入失敗、兩個外掛都不能用（改回原名才恢復）。Codex 版是把檔案複製走，裝完後不依賴這個資料夾，但以後移除、升級都要用到它，所以也請留著。

2　Claude 桌面 App（Code 分頁）

只用 ChatGPT／Codex 的人，跳到第 3 章。

本章的 App 畫面描述（分頁名稱、選資料夾的位置、確認視窗的樣子和次數、系統匣選單）還沒在真的 App 上核對過，以你看到的為準。

2-1　開一個新的 Code 對話，資料夾選包裹資料夾

要做什麼打開 Claude 桌面 App，切到 Code 分頁，開一個新對話。選工作資料夾時，選你剛剛解壓的 C:\dev-bingfa-1.0。畫面可能略有不同——重點是「這個對話的資料夾是包裹資料夾」。
如果畫面讓你選「本機（Local）」或「雲端（Cloud／Remote）」之類的工作方式，選本機：雲端的 AI 讀不到你電腦上的 C:\dev-bingfa-1.0，第一步就會失敗。（選項的實際名稱沒核對過。）
看到這個代表成功可以在對話框打字，畫面上某處顯示你選的資料夾。
沒看到的話找不到 Code 分頁或選資料夾的地方：可能是 App 版本或帳號沒有這個功能。拍下畫面給維護人。

2-2　對 AI 說這一句話

要做什麼複製下面這句，貼到對話框送出。如果你的包裹資料夾不是 C:\dev-bingfa-1.0，把路徑換成你的。
請讀 C:\dev-bingfa-1.0\安裝指示-ClaudeCode.md 這個檔案，照著幫我安裝。

怎麼拿到正確的完整路徑：在檔案總管找到 安裝指示-ClaudeCode.md，按住 Shift 再按右鍵，選「複製為路徑」（選單文字可能略有不同），貼上時會多一組雙引號，留著或刪掉都可以。

看到這個代表成功AI 開始照指示做。第一步做完，它會回報一行像 OK 包裹位置：C:\dev-bingfa-1.0　版本：1.0，並提醒你「這個包裹資料夾要一直留在原地」。
沒看到的話
  • AI 說找不到檔案 → 路徑打錯了，照上面的方法重新複製路徑。
  • AI 回 STOP 包裹還在壓縮檔或暫存資料夾裡 → 回到第 1 章，解壓到固定資料夾。
  • AI 說它不能執行指令 → 看第 7 章。

2-3　AI 會跳出哪些「允許」確認

AI 每執行一段指令，App 可能會跳出一個確認，問你要不要讓它執行。確認視窗裡顯示的通常是一段指令（英文和符號），不是下表的中文。怎麼判斷：

  • 看得到 claude.exe、plugin、CLAUDE.md、dev-bingfa、離線副本、python 這些字 → 按允許。
  • 看到 login、auth、password、ssh、token，或要你改權限模式 → 按拒絕，拍下畫面給維護人。

下表是 AI 照指示會做的事，可以對照它正在做哪一步：

第幾步AI 在做什麼會改你電腦上的東西嗎
1確認包裹資料夾的位置、版本不會（只讀）
2找到 App 內附的 Claude Code 程式，查已經裝了什麼、有沒有 Python不會（只讀）
3裝 Matt 的工具：先試從網路（GitHub）下載，可能要等一兩分鐘；連不上就改用包裹裡的離線副本（會再跳一次確認）會：加一個外掛
4裝本包裹的主外掛 dev-bingfa會：加一個外掛
5有 Python 才做：裝存檔自動檢查 dev-bingfa-check會：加一個外掛
6把規則加到你的規則檔 CLAUDE.md 尾端（先備份原檔）會：改規則檔，只加不刪
7最後自我檢查不會（只讀）
要做什麼上表這些事，按「允許」。如果 AI 或視窗要你登入、輸入密碼、設定 SSH 金鑰、執行 gh auth login、或修改權限設定 → 一律按拒絕，拍下畫面給維護人。安裝指示裡沒有任何一步需要這些。

第 3 步如果先試網路失敗、再改用離線副本，就會多一次確認；所以確認的次數每個人不一定一樣。

AI 也可能在對話裡停下來問你：

  • 「確定要讓我修改規則檔／加入外掛來源嗎？」→ 回答：要，照指示做。
  • 「你的電腦好像已經用別的方式裝過 Matt Pocock 的工具……要我跳過 Matt 的工具、只裝其他部分嗎？」→ 一般回答 跳過（不然每個工具會出現兩次）。不確定就問維護人。
  • 「App 跳出（或擋下）了一個確認，請按允許，我再執行一次」→ 按允許，或回答它可以再試。你不想允許就說不要，它會停下來回報。

項目正常會看到要注意

2-5　完全關閉 App，再重新打開

要做什麼關掉 Claude 桌面 App 的視窗之後，到螢幕右下角的系統匣（時鐘旁邊的小圖示區，可能要按「^」展開）找到 Claude 的圖示，按右鍵選結束（選單文字可能略有不同）。然後重新打開 App。
看到這個代表成功系統匣裡的 Claude 圖示消失後再重開。保險起見要完全結束；只關視窗，新裝的東西可能不會載入。

2-6　確認裝好了

要做什麼在 Code 分頁開一個新對話，在對話框用鍵盤按一下 / 鍵（斜線，在右下方 Shift 旁邊）。
看到這個代表成功跳出一份清單，裡面有 /dev-bingfa:commit、/dev-bingfa:brownfield-recon、/mattpocock-skills:grill-me 這類名字（前面是外掛名、冒號後面是技能名）。
未實測 #1重開後清單裡會不會出現這些名字，還沒在真的 App 上看過。 如果不一樣：先確定 2-5 有真的完全關閉、開的是新對話；還是沒有 → 照第 9 章「看不到指令」做，再把清單畫面和 AI 的結果表給維護人。
未實測 #7直接打短名稱（例如 /grill-me）能不能用，沒有測過，所以所有說明書一律教完整名稱。 如果不一樣：短名稱沒反應 → 打完整名稱（/mattpocock-skills:grill-me）。

3　ChatGPT 桌面 App 裡的 Codex

Codex 現在是 ChatGPT 桌面 App 裡的一個模式。這條路和 Claude 版最大的不同：AI 是把檔案複製到你的使用者資料夾，不用任何額外程式。

本章的 App 畫面描述（Codex 的位置、加專案的按鈕、確認視窗的樣子和次數、系統匣選單）還沒在真的 App 上核對過，以你看到的為準。

3-1　切到 Codex，把包裹資料夾加成專案

要做什麼打開 ChatGPT 桌面 App，切到 Codex。把 C:\dev-bingfa-1.0 加成一個專案（官方文件裡叫「Add new project」），然後在這個專案開一個新對話。畫面可能略有不同——重點是「這個對話的資料夾是包裹資料夾」。
如果畫面讓你選「本機（Local）」或「雲端（Cloud）」之類的工作方式，選本機：雲端的 AI 讀不到你電腦上的資料夾。（選項的實際名稱沒核對過。）
看到這個代表成功在這個專案底下可以打字對話。
沒看到的話找不到 Codex 或加專案的地方 → 拍下畫面給維護人。

3-2　對 AI 說這一句話

請讀 C:\dev-bingfa-1.0\安裝指示-Codex.md 這個檔案，照著幫我安裝。

更新到新版

維護人發新版時，會在 更新紀錄.md 寫「要不要重裝」。需要重裝時：

  • Claude 版：把新版解壓到另一個固定資料夾（例如 C:\dev-bingfa-1.1），在新資料夾照第 2 章再說一次那句話。AI 會把本包裹的外掛（如果 Matt 的工具是用離線副本裝的，也包括它）改成讀新資料夾。舊資料夾能不能刪，看結果表：表上明說舊資料夾已經不用、可以刪，才刪；表上沒說，或說「還不能刪」，就留著，有疑問問維護人。
  • Codex 版：新版的檔案和舊的不一樣，直接重裝會被判成 CONFLICT 而停下來。所以要先用舊版包裹移除，移除那句話最後加上 Matt 的工具也一起移除。（不然 Matt 的工具會一直停在舊版，重裝時還會問你要不要跳過）；再用新版包裹安裝。
  • 規則檔重裝只會換掉標記中間那段，不會加兩次，你的個人偏好不會被動（這點在隔離環境實測過）。

退回舊版

舊版的壓縮檔會保留在公司共用資料夾。退回的做法和更新一樣，只是方向相反：

  • Claude 版：把舊版解壓到它自己的資料夾，在那個資料夾說一次安裝句。資料夾能不能刪，一樣看結果表。
  • Codex 版：先用「現在這一版」的包裹移除（加上 Matt 的工具也一起移除。），再用舊版的包裹安裝。
未實測 #11升級和退回整條流程沒有在真的 App 裡從頭做過；「改讀新資料夾」和「結果表、移除回報告訴你資料夾能不能刪」已寫進安裝指示和移除指示，指令本身在隔離環境試過。 如果不一樣：結果表沒提舊資料夾能不能刪，或你拿不準 → 兩個資料夾都留著，把結果表原文給維護人。

未實測 #9真的 App 裡的 AI 會不會拒絕、聽了這句會不會照做，沒有測過。 如果不一樣：它還是不肯 → 用第 7 章的備案，規則那一步你自己貼（Claude 版是備案的 A6，Codex 版是 B4）。

打 /（Claude）或 $（Codex）看不到新的指令

  1. 確定已經完全關閉 App（系統匣的圖示也要結束），再重開。
  2. 開一個新對話再試，舊對話不會更新。
  3. Claude 版：確定包裹資料夾沒有被搬動、改名、刪除。
  4. 都試過還是沒有 → 把畫面和安裝時 AI 給的結果表，交給維護人。

裝到一半停下來了

AI 照指示，遇到任何沒寫到的情況都會立刻停下來，說「卡在第幾步、看到什麼、什麼還沒裝」。這是設計好的，不是壞掉。

  • 把 AI 的回報原文整段複製，交給維護人。不要叫 AI「自己想辦法」或改用別的方式裝。
  • 維護人說可以重試時，再說一次那句話即可。重複安裝不會把規則加兩次、不會重複複製（隔離環境實測過）。

AI 說找不到 Claude Code 程式（STOP 找不到 Claude Code 程式）

代表 App 內附的程式不在預期的位置。給維護人看這段訊息。

12　看不懂的詞

詞意思
技能（skill）寫好的一套做事步驟。AI 讀了就照著做。例如 grill-me 是「追問需求」的步驟。
外掛（plugin）把好幾個技能、助手打包在一起的安裝單位。Claude 版用外掛安裝。
外掛目錄（marketplace）告訴 App「外掛放在哪裡」的清單。本包裹的 外掛 資料夾就是一份。
助手（subagent）主對話派出去分頭做事的另一個 AI，做完把結論交回來。
規則檔AI 每次對話都會先讀的說明檔。Claude 讀 CLAUDE.md，Codex、Cursor、Antigravity 讀 AGENTS.md。
標記規則檔裡 <!-- dev-bingfa:start …--> 和 <!-- dev-bingfa:end --> 這兩行。AI 會把它們當註記看，不影響規則；安裝程序靠它們找到「本包裹那一段」。
前綴名字前面加的外掛名，例如 /dev-bingfa:commit 的 dev-bingfa:。
Git一個免費程式，能把檔案的每一個版本存下來，隨時可以比較或退回。
提交（commit）用 Git 存一個版本，像遊戲的存檔點。
GitHub放 Git 專案的網站。Matt 的工具官方版放在那裡。
離線副本包裹裡附的一份 Matt 工具，連不上 GitHub 時用。
Python一種程式語言；存檔自動檢查是用它寫的，所以要有它才能裝。
Node.js／npx另一種執行程式；基本版用 npx 這個指令安裝 Matt 的工具。
PowerShellWindows 內建、可以打指令的視窗。安裝時 AI 用它執行指令。
系統匣螢幕右下角、時鐘旁邊放小圖示的地方。
%USERPROFILE%「你的使用者資料夾」的代號，通常是 C:\Users\你的帳號。
UTF-8一種存文字檔的格式（編碼）。記事本存檔時選它，中文才不會出問題。
專案資料夾放某一個工作所有檔案的資料夾。
