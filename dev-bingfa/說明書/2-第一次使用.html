0　這份教學怎麼用

你會跟著做一個很小的工具：午餐分帳計算機。它是一個網頁檔，用滑鼠按兩下就能在瀏覽器打開，輸入總金額和人數，算出每個人要付多少。選它的理由：

  • 不用裝任何額外軟體，不用帳號、不用網路、不碰公司系統。
  • 做出來好不好，你自己打開來用就知道，不需要看得懂程式。
  • 夠小。第一次大約要 1 小時（AI 會問好幾輪問題、跑好幾輪測試）；做完任務卡 01 就算完成，其他任務卡之後再做。

整條流程（主線）

準備 → 1 追問需求 → 2 寫規格 → 3 切任務卡 → 4 先測試再實作 → 5 獨立審查 → 6 交付與檢討

每一步都寫：這一步在做什麼、你要打什麼、AI 會回什麼樣的東西、你要做的決定、怎樣算完成、常見卡住點。

開始前要有的

  • 已經照說明書一裝好，而且重開過 App。
  • Git（存版本的免費程式）最好有。沒有也能練習，但「存版本」和「獨立審查」兩步要改用替代做法，下面會寫。

為什麼用 grill-me？這是一次性的小練習。長期的專案改用 grill-with-docs（/mattpocock-skills:grill-with-docs／$grill-with-docs）：它問法一樣，但會順手把專案用語記到 GLOSSARY.md、把重要決定記成決策紀錄。

AI 會回什麼

一輪一輪的編號問題。每一題都附上它建議的答案，而且問法設計成「你回答『是』就等於接受建議」。它能自己查到的事實不會來問你，只問需要你決定的事。

大概長這樣 示意
❓ Q1 - 服務費：很多餐廳會加收一成服務費。計算機要不要有「加一成服務費」的選項？
➡️ 建議：要，做成一個勾選框，預設不勾。

❓ Q2 - 除不盡的零頭：1000 元 3 個人分，每人 333.33 元。要怎麼處理？
➡️ 建議：每人金額無條件進位到整數元，並顯示「多收了幾元」。

你要做的決定

  • 每一題回答「是」，或寫出你要的答案，例如：Q1 是；Q2 改成四捨五入。
  • 這個練習會碰到的典型決定：服務費要不要算、零頭怎麼處理、人數最多幾個、打錯（例如人數填 0）時畫面要說什麼。
  • 測試要怎麼讓你看得到：建議回答「測試做成一個我按兩下就能打開的自我測試頁，打開就看得到每一項是通過還是失敗」。這樣不管電腦上有沒有其他程式，你都能自己確認。
怎樣算完成AI 說已經沒有要問的了，並請你確認「我們的理解一致」。你回答同意。這一步 AI 還不會寫程式，這是正常的。
常見卡住點
  • 問題太多 → 回它：這是一個小練習，請把範圍縮到最小，剩下的都用你建議的答案。
  • AI 直接開始寫程式 → 請它停下來：先不要寫程式，我們還在問需求。
未實測 #3（Codex）grill-me、grill-with-docs、retro 的說明檔叫 AI「用 Skill tool 去叫另一個技能」。Skill tool 是 Claude 的工具名，Codex 有沒有同樣的東西不知道。 如果不一樣：AI 說找不到 Skill tool → 回它：請直接照 grilling 這個 skill 的步驟做。grill-with-docs 回：請直接照 grilling 和 domain-modeling 這兩個 skill 的步驟做。retro 回：請先讀 writing-for-agents 這個 skill，再照 retro 的步驟做。

3　第 2 步：寫規格

這一步在做什麼：把剛剛問清楚的東西，整理成一份寫下來的規格。之後每一步都照這份做，大家看的是同一份。

你要打什麼（在同一個對話接著打）

Claude 桌面 App
/mattpocock-skills:to-spec
Codex
$to-spec

AI 會回什麼

它不會再問一輪，而是直接整理剛才的對話。寫之前，它會先跟你確認「要從哪裡測試」——它叫 seam，意思是「測試從哪個入口檢查」，例如「給總金額、人數、要不要服務費 → 檢查每人金額」。確認後，它把規格寫成一個檔案，位置大概是 .scratch\午餐分帳之類的名稱\spec.md。

規格裡會有這幾段（英文標題）：Problem Statement（問題）、Solution（解法）、User Stories（一長串「身為……我想要……以便……」）、Implementation Decisions（實作上的決定）、Testing Decisions（測試怎麼做）、Out of Scope（這次不做的事）。

你要做的決定

  • 測試入口：聽起來是「從使用者會做的事去檢查」就同意。
  • 用記事本打開 spec.md，至少讀 Problem Statement、Solution、Out of Scope 三段。有不對的地方，直接用中文告訴 AI 要改什麼。
怎樣算完成spec.md 存在，你讀過，覺得「對，就是要做這個、不做那些」。
常見卡住點
  • AI 說要先跑 setup-matt-pocock-skills → 回去做 1-4。
  • User Stories 很長 → 正常，它的設計就是列很多。重點看 Out of Scope 有沒有把不要的東西排除掉。

6　第 5 步：獨立審查

這一步在做什麼：找「另一雙眼睛」檢查剛做好的東西。

12　看不懂的詞

詞意思
技能（skill）寫好的一套做事步驟，AI 照著做。
規格（spec）寫下來的「要做什麼、不做什麼」。
任務卡（ticket）規格切出來的一小塊工作，一張一個檔案，做完能單獨看到成果。
驗收條件任務卡裡的打勾清單，全部做到才算完成。
測試一段自動檢查「程式算得對不對」的程式。紅燈＝沒通過，綠燈＝通過。
先測試再實作（TDD）先寫一個會失敗的測試，再寫讓它通過的程式，一小塊一小塊做。
測試入口（seam）測試從哪裡檢查，例如「給金額和人數，看每人金額」。
助手（subagent）主對話派出去分頭做事的另一個 AI。
獨立審查由看不到之前對話的 AI 來檢查改動。
Git／提交（commit）Git 是存版本的程式；提交就是存一個版本，像遊戲的存檔點。
版本編號每次提交 Git 給的一串英文數字，用來指出「哪一個存檔點」。
GitHub／GitHub Issues放 Git 專案的網站；Issues 是它的任務清單功能。
PR（pull request）請別人審核並合併改動的申請。
規則檔AI 每次對話會先讀的說明檔（CLAUDE.md 或 AGENTS.md）。
.scratch專案資料夾裡放規格和任務卡的資料夾（名字前面有一個點）。
交接文件handoff 寫的進度摘要，讓新對話能接著做。
Edge 無頭模式讓 Windows 內建的 Edge 瀏覽器在背景打開網頁、不顯示視窗，把頁面上的結果印出來。AI 用它來看自我測試頁的結果。
