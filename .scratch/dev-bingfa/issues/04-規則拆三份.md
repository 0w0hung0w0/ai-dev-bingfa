# 04 規則拆三份

依賴：02（懸空引用清單來自 01）

## 目的

把使用者的 `~/.claude/CLAUDE.md` 改寫成同事可用的三份規則（規格第 5 節）。

## 要做什麼

1. **通用規則**：所有工具都用。內容只有一份，產出兩個檔名（`CLAUDE.md`、`AGENTS.md`），並有辦法確認兩份內容一致。
   - 原第 6 節流程改寫成 Matt 主線：追問需求 → 寫規格 → 切任務卡 → 先測試再實作 → 獨立審查 → 交付與檢討。
   - 名詞只記在 `GLOSSARY.md`；移除「以 `CONTEXT_MAP.md` 的 Language 節為準」。
   - 規劃與實作分工只留原則，不寫模型名稱。
   - 任務卡預設放專案資料夾的本地檔案。
   - 移除對被排除工具的引用。
2. **Claude 專用附錄**：只有 Claude Code 才適用的內容（助手名稱、`/commit`、檢查腳本等）。
3. **個人偏好範例**：回覆語言、驗收方式、模型名稱等，寫成同事看得懂、可以自己改的範本。

## 不做什麼

- 不修改 `~/.claude/CLAUDE.md`。
- 不新增原規則沒有的新規矩（只做拆分與規格第 5 節指定的改寫）。
- 不寫安裝步驟（那是 09）。

## 完成的樣子

- 一張對照表：原規則每一節 → 去了三份中的哪一份、有沒有改寫、為什麼。沒有任何一節「不見了卻沒說」。
- `CLAUDE.md` 與 `AGENTS.md` 兩份通用規則內容相同，附比對指令與結果。
- 通用規則裡搜尋不到模型名稱、被排除工具名稱、「Language 節」。
- 哪些內容歸「通用」還是「Claude 專用」是判斷題，拿不準的列出來請使用者裁決。
