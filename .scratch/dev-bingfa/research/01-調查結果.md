## 三、待解的一點：Matt 的 skill 名稱能不能照用

使用者的規則裡提到 `grill-me`、`grill-with-docs`、`handoff`、`wayfinder`、`triage`、`to-tickets`。

**結論**：六個名字在目前的外掛版本裡**都存在**，而且**全部是「只能由人手動叫」**的 skill（frontmatter 寫 `disable-model-invocation: true`）。所以：

- AI 自己不能啟動它們；規則裡寫「建議使用者打 `/grill-me`」這種說法是可行的，前提是由人來打。
- 01a 發現這幾個名字「不在 AI 看得到的 skill 清單裡」，原因就是它們設定為只能手動叫（AI 的清單本來就不列這種 skill），**不是**名字消失了。
- Matt 的 README 也寫：手動 skill 可以呼叫自動 skill，但不能呼叫另一個手動 skill。

**在 Claude Code 怎麼叫**：外掛裡的 skill 正式名稱有前綴，例如 `/mattpocock-skills:grill-me`（01b 第 8 題的命名規則；實測驗證輸出也是 `外掛名:skill名` 的格式）。直接打短名 `/grill-me` 能不能用：**未確認**（本報告沒有實測）。
**在 Codex 怎麼叫**：清單上的名稱是 `外掛名:skill名`，用 `$` 或 `/skills` 選（01b 第 3、5 題）。Codex 是否也遵守 `disable-model-invocation`：**未確認**（01b 推測會被忽略）。

**對同事的影響**：名字本身會有效（同事照官方方式裝的是同一個外掛），但規則和說明書裡應寫完整名稱 `/mattpocock-skills:grill-me`，或至少說明「也可能要打完整名稱」，直到卡 12 實測短名能不能用。這影響卡 04（規則）和卡 09–11（說明書）。

**證據**：

- 01b 第 9 題：外掛 `plugin.json` 的 `skills` 陣列（1.3.2 版）把這六個列為「只能使用者手動叫」。
- 本機唯讀檢查（只看資料夾名稱與 SKILL.md 開頭幾行）：`~/.claude/plugins/cache/claude-plugins-official/mattpocock-skills/1.3.1/`，六個 SKILL.md 的 `name` 與資料夾名相同，都有 `disable-model-invocation: true`，且都列在該版 `.claude-plugin/plugin.json` 裡。對照組 `grilling` 沒有這一行（AI 可以自動叫）。
- 注意版本差：本機是 1.3.1，01b 讀的 GitHub 是 1.3.2；兩版這六個名字的狀態一致。

**信心**：高（名字存在、只能手動叫）；未確認（短名能否用、Codex 是否遵守手動限制）。

## 四、主對話已做的決定（要回報給使用者）

以下由主對話（規劃者）依調查結果決定，交給使用者知悉；使用者若不同意可推翻。

1. **Claude Code 和 Codex 共用一個外掛資料夾**，只用 `.claude-plugin/plugin.json` 加 `.claude-plugin/marketplace.json`。不放 `.agents/plugins/marketplace.json`（兩份並存時 Codex 會選那份，內容容易不同步），也不放根目錄 `plugin.json`（本機 Codex 0.140.0 不支援）。
2. **skill 叫用時保留外掛前綴**，例如 `/dev-bingfa:commit`。不另外複製到 `~/.claude/skills`。
3. **`commit` 做成 skill**（兩個工具共用），不做成只有 Claude Code 能用的指令。理由：Codex 的自訂指令已被官方標為淘汰，而且不能放進外掛。
4. **Python 檢查腳本做成另一個選用外掛 `dev-bingfa-check`**，放在同一個 marketplace 裡，只有電腦有 Python 才裝。說明書告訴沒有 Python 的人跳過，並直接寫「這項沒啟用」。
5. **Codex 的助手設定用 TOML 檔，複製到 `~/.codex/agents/`**。explorer 在 Codex 上改名為 `bingfa-explorer`，避免蓋掉 Codex 內建的 `explorer`；另外兩個在 Codex 上也加 `bingfa-` 前綴，保持一致（Claude Code 上不加）。
6. **Codex 的檢查腳本是選配**，除非卡 06 實際讓它跑起來，否則說明書標「未實測成功」。原因：這台電腦有公司管控的 Codex hook 設定（`C:\ProgramData\OpenAI\Codex\requirements.toml`），自訂 hook 測不到執行。
7. **web-search-modules 維持原本的簡體中文**（給 AI 讀，不是給人讀），只修正路徑和 POSIX 的 `date` 指令（Windows 上不能用）。
