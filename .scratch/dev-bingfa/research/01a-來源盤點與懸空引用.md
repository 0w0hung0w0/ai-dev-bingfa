## 6. `check_silence.py` 細節

**做什麼**：PostToolUse hook。讀 stdin 的 hook JSON，取出剛被寫/改的檔案路徑；只處理副檔名 `.py`（`:44`）且路徑不符 `(^|[\\/])(test_|conftest)`（`:47`，排除測試檔）。用 `ast.parse` 走語法樹（`:107-127`），找出 `try` 的 handler 同時滿足：(a) 廣泛捕捉——裸 `except:`、`Exception`、`BaseException`（含 tuple 內出現）（`:63-70`）；(b) handler body 恰好只有一個 `pass`（`:122`）；(c) 該 `try` body **不是**「每一句都是 import 或 `sys.stdout/stderr = ...`」的防呆樣板（`:73-94`）。語法錯誤（寫到一半）回空清單不打擾。

**依賴的 stdin JSON 欄位**（`:145-146`）：
- `tool_input.file_path`（優先）
- 退而求其次 `tool_response.filePath`
- 兩者皆無就 exit 0。不讀 `hook_event_name`、`tool_name`、`cwd` 等其他欄位。

**Python 版本與函式庫**：只用標準庫 `ast`、`json`、`re`、`sys`、`pathlib`；有 `from __future__ import annotations`（`:35`），所以 `list[tuple[int, str]]` 型別註記在 3.7+ 可用。實務上需 Python 3.7 以上（3.8+ 較保險）；無第三方套件。執行指令為 `python`，機器上要有此指令（macOS/Linux 常只有 `python3`）。

**輸出與 exit code**：
- 讀 stdin 或解析 JSON 失敗：stderr 寫 `[check_silence] 讀取輸入失敗，略過本次檢查：{e}`，**exit 0**（`:141-143`）。
- 無路徑、非 .py、測試檔、讀檔失敗、沒命中：**exit 0**，無輸出（`:147-160`；讀檔失敗那處 `:155-156` 本身是 `except Exception: return 0`，不是 `pass`，所以不會被自己抓到）。
- 有命中：stderr 寫繁中警告，列最多 5 處（行號＋原文），要求說明「上游怎麼知道失敗、使用者在哪裡看得到」，**exit 2**（`:162-176`）。PostToolUse 的 exit 2 會把 stderr 回饋給 Claude，不中斷流程（檔案已寫入）。
- 所有 stderr 以 UTF-8 bytes 寫出（`:50-60`），stdin 以 bytes 讀再 UTF-8 解碼（`:139-140`），專為 Windows cp950 編碼問題處理。
- settings 設 `timeout: 10` 秒。

**限制**：只看 Python；matcher `Write|Edit` 不涵蓋 `MultiEdit`/`NotebookEdit`；只抓 `pass`，`except Exception: ...`（Ellipsis）、`continue`、`return None` 等同樣靜默的寫法不抓（docstring 明說刻意寧漏勿吵）。
