### 4. 提交（`commit/SKILL.md`，新增）

原本是 Claude Code 專用的「指令」檔 `~/.claude/commands/commit.md`，改寫成兩個工具都能讀的 skill。

| 位置 | 改之前 | 改之後 | 為什麼 |
|---|---|---|---|
| 開頭設定 | 沒有 `name` | 加上 `name: commit` | skill 必須有名稱，兩個工具才找得到 |
| 開頭設定 `description` | 檢視變更並建立 git commit(強制使用 opus) | 檢視變更並建立 git commit。只在使用者明確要求提交時使用，不要自己主動提交 | 拿掉模型名稱；並寫明只能由使用者叫用（Codex 不認得下一行的設定，靠這句說明） |
| 開頭設定 | `model: opus` | 拿掉 | 用哪個模型是個人偏好；01b 調查報告沒有證據顯示這一行在 Codex 的 skill 裡無害 |
| 開頭設定 | （沒有） | 加上 `disable-model-invocation: true` | 讓 Claude Code 裡只有人能叫它，AI 不會自己決定提交 |
| 開頭設定 `allowed-tools` | 只放行 git status/diff/log/add/commit | 保留不變 | 維持原本「只能用這幾個 git 指令」的行為 |
| 第 2 點 | 只 stage 相關檔案，不要用 `git add -A` 盲目全加 | 逐一寫出檔案路徑（`git add <路徑>`），不要用 `git add -A` 或 `git add .`，也不要用 `git commit -a` / `--all`（含 `-am`） | 規格第 9 節兩個都禁止，原文只寫了一個；`allowed-tools` 放行 `git commit`，所以 `-a` 會繞過「明確路徑」（審查 S7） |
| 新增第 5 點 | （原文沒寫） | 只 commit，不要 push | 規格第 9 節：不推送 |

**刻意新增、請使用者知悉**：「只用明確路徑 stage」「不要 `git commit -a`」「不 push」三條是原 command 沒有的新規矩（來源是規格第 9 節，原本是限制本專案施工用的）。內容是安全的，所以保留給同事用。
`commit` 依任務卡原本屬於卡 05，實際在卡 03 做了；卡 05 的驗收（`/commit` 出現在清單）要改成 `/dev-bingfa:commit`。
| 最後一行 | `$ARGUMENTS`（Claude Code 指令專用的「把使用者打的字塞進來」） | 改成一句話：使用者叫用時若附帶說明就照著做 | `$ARGUMENTS` 在 Codex 沒有意義 |

## 三、判斷（沒有人明確指示、由我決定的地方）

1. **`### Flagged Ambiguities` 也拿掉**：它記的是「有歧義的詞最後怎麼解釋」，屬於名詞表。改成一句話叫 AI 把這類詞記到 `GLOSSARY.md`。
2. **`commit` 拿掉 `model:`**：01b 沒有說這一行在兩個工具的 skill 裡都無害，所以照規則拿掉。
3. **`commit` 加 `disable-model-invocation: true`、保留 `allowed-tools`**：前者讓 Claude Code 裡只能由人叫；後者維持原本的權限範圍。Codex 是否遵守這兩行**未確認**（01b 推測會忽略），所以在 description 裡也用文字寫「只在使用者明確要求時使用」。沒有另外加 Codex 專用的 `agents/openai.yaml`（不在這張卡的要求裡）。
4. **探勘助手不寫名稱**：原本寫了 Claude Code 與 Codex 兩個名稱，審查 S6 指出名稱可能不對、也沒人守；規劃者裁決改成「有調查用助手就委派，確切名稱見規則 §5 與工具附錄；沒有就自己做」。
