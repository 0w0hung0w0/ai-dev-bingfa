## 更正：換行格式（2026-11-24 後續修正）

**第 1、2 節的「逐檔相同」比錯了對象。** 當時這台電腦的 Git 設定 `core.autocrlf=true`，所以上游 clone（`clone08/skills`）和本 repo 的工作目錄，在取出檔案時**都被 Git 把換行改成 CRLF**。拿兩份「都被改過」的檔案互相比，當然一樣；但它們都不等於原作者 repo 裡的原檔（原檔是 LF）。第 2 節的 LICENSE 雜湊 `4981c5f6…` 就是 CRLF 版。

### 修正做法

1. `.gitattributes` 已把 `dev-bingfa/離線副本/mattpocock-skills/**` 設成 `-text -eol`（不做換行轉換）。
2. 先確認這個資料夾沒有未提交的改動：`git status --short -- "dev-bingfa/離線副本"` → 空白（0 行）。
3. 重新取出：`git checkout -- "dev-bingfa/離線副本/mattpocock-skills"`。只打這一行**沒有效果**（Git 看檔案時間沒變就跳過，取出後仍是 `w/crlf`），所以先 `touch` 這些檔案（只改修改時間，不改內容），再 checkout 一次。之後 `git ls-files --eol`：186 個 `i/lf w/lf attr/-text`、1 個空檔 `i/none w/none`，`git status` 仍然乾淨。
4. 用**不轉換換行**的方式重新 clone 上游：`git -c core.autocrlf=false clone https://github.com/mattpocock/skills`，再 `checkout abeeaf95660ba9e8b7c753eb38f441ca707a8823`，並把這份 clone 的 `core.autocrlf` 設成 `false`（放在 `.scratch/dev-bingfa/research/sandbox/up-eol/skills`）。上游 `git ls-files --eol`：186 個 `i/lf w/lf`、1 個空檔。

| 工作目錄每個檔的 SHA-256 vs 上游 clone 每個檔的 SHA-256 | 187 vs 187 | **完全相同**（`diff` 無輸出） |
| 本 repo 已提交的 blob 雜湊（`git ls-tree -r HEAD`）vs 上游 commit 的 blob 雜湊 | 187 vs 187 | **完全相同** |
