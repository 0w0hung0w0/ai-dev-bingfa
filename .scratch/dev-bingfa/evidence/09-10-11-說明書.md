## 4. 寫作時發現的事（要維護人知道）

1. **Claude 版升級時，舊資料夾可能還不能刪。** 如果 Matt 的工具當初是用離線副本裝的（`mattpocock-offline` 是用路徑登記的），用新版包裹重裝時，安裝指示第 3 步看到「Matt 已經有了」會整步跳過，Matt 的工具就繼續讀**舊資料夾**的離線副本。刪掉舊資料夾，Matt 的工具可能失效。說明書一第 8 章已寫「舊資料夾先不要刪，要刪之前先問維護人」。安裝指示本身沒有處理這個情況（推論，沒有實測）。
2. **`code-review` 比較的是「存檔點到目前最新的存檔」，不是還沒存的改動。** 它的步驟寫 `git diff <fixed-point>...HEAD`，而且 diff 是空的就要停。所以說明書二把順序寫成：切完任務卡先存一次版本（起點）→ 做完任務卡再存一次 → 才審查。沒有 Git 時改用「開全新對話手動審查」（未實測）。
3. **Git 第一次提交要設定名字和 email。** 新電腦上 `git commit` 會失敗。`commit` 技能的 `allowed-tools` 只有 git status/diff/log/add/commit，不含 `git config`。說明書二只寫「AI 會告訴你，要用什麼名字由你決定，不確定就問維護人、這次先跳過存版本」，沒有教設定方法。
4. **規格 §11 第 6 項（同名書）**：研究 01 的決定是「不寫進說明書」，但這次的交辦要「列出 §11 每一項」，所以說明書一第 10 章寫了一句中性的現況。若要維持研究 01 的決定，刪掉那一列即可。
5. 說明書一第 5 章「沒有 Node.js 時，把離線副本的資料夾複製到專案 `.agents\skills\`」是比照 Codex 備案推出來的，包裹裡其他文件都沒有這條路，已標未實測。
