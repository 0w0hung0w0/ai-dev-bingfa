## Should-fix

**S1 個人偏好範本被放進「安裝程序管理」的區塊裡**
- 位置：`安裝指示-Codex.md:118-123`、`安裝指示-ClaudeCode.md:161-166`、`規則/個人偏好範例.md`（Models per role 那一節）。
- 問題：
  - 區塊裡留著 `【請改：繁體中文】`、`【請改：Fable】` 這類還沒改的範本字，AI 會直接讀到。
  - 結果表第 4 句又叫同事把偏好寫在 `<!-- dev-bingfa:end -->` 下面，檔案裡就會有兩段 Personal Preferences，看哪一段要靠猜。
  - Codex 的規則檔裡出現 Claude 的模型名稱（Fable、Opus、Sonnet），對 Codex 沒有意義。
- 建議：區塊裡只放通用規則和工具附錄。偏好範本只在第一次安裝時放到結束標記**下面**，屬於使用者自己的內容，重裝不換、移除也不拿掉。如果要保留在區塊裡，就把範本字換成實際的預設值。Codex 版的模型那一節建議改成：「主對話與實作：用你在 Codex 模型選單裡較強的那個；機械式小修改：較快的那個。沒有填就照通用規則的預設。」

**S2 給同事看的三行，沒先告訴他 AI 可能會在對話裡停下來問**
- 位置：兩份安裝指示的第 3～6 行。
- 問題：謹慎的 AI 在改 `CLAUDE.md`／`AGENTS.md`（等於改自己的規則）、或從 GitHub 加 marketplace 之前，可能會先在對話裡問「確定嗎？」。Codex 寫入使用者資料夾也可能要求提升權限。三行說明只講了「允許」視窗，沒講文字確認；也沒說要先解壓到固定資料夾。
- 建議：加一句「AI 如果問你要不要讓它修改規則檔或加外掛目錄，回答『要，照指示做』」，再加一句「先把壓縮檔整個解壓到固定資料夾（例如 `C:\dev-bingfa-1.0`）」。

**S3 Codex：之前用別的方式裝過 Matt 的工具，整個安裝會被擋下**
- 位置：`安裝指示-Codex.md:54-91`。
- 問題：如果同事之前用 skills.sh／`npx` 裝過 Matt 的工具，`~/.agents/skills/grill-me` 這類資料夾的版本會不一樣，於是全部判成 `CONFLICT`，一樣東西都不裝。安全，但同事只能卡住找維護人。
- 建議：仿照 Claude 版的 `MATT-LOOSE`。如果衝突**只出在** Matt 的 skill，就問使用者「要跳過 Matt 的工具、只裝其他部分嗎？」。

**S4 移除後規則檔沒有完全還原，訊息卻說是原本的內容**
- 位置：`移除指示.md:76,81,163,168`，原因在 `安裝指示-*.md` 的 `$sep`（Codex 第 144 行、Claude 第 187 行）。
- 重現：原檔沒有結尾換行時，移除後多了一個 `\n`（109 → 110 位元組），但輸出寫「這是你自己原本的內容」。
- 建議：安裝時如果補了換行，就在開始標記裡記下來，例如 `<!-- dev-bingfa:start 1.0 nl -->`；移除時看到 `nl`，就連前面那個 `\n` 一起拿掉。比較省事的做法是把訊息改成「原本內容（可能多一個結尾換行）」。

**S5 `貼指令備案.md` 的步驟和 AI 版不一樣**
- `貼指令備案.md:36`：A2 沒有檢查 `MATT-LOOSE`。
- `貼指令備案.md:70`：A5 只試 `py -3`，沒試 `python`／`python3`，結果可能和 AI 版判斷不同。
- `貼指令備案.md:132-134`：B3 說「選取全部資料夾（20 個）」，但 `engineering`、`productivity` 裡各還有一個 `README.md` 檔。同事按全選會一起複製，第二次貼上就跳出同名衝突。另外「不要複製」的清單漏了 `deprecated`。

## Nit

- 先備份、後檢查標記（Codex 第 131-136 行、Claude 第 174-179 行）：`STOP` 時也會留下一份備份。同一秒內跑兩次，第二份會蓋掉第一份。建議把備份移到檢查通過之後，檔名加到毫秒。
- 換掉區塊時，區塊一律用 LF；原檔是 CRLF 時，檔案會混用兩種換行。
- `安裝指示-Codex.md:69` 的 `Test-Path`（沒有加 `-LiteralPath`）：`CODEX_HOME` 裡有 `[` 時，萬用字元會判斷錯，可能把已裝的 Matt 外掛判成沒有，又複製一份。這是推論，沒有實測。
- 移除 B1／B2 用「內容和包裹一模一樣」來判斷。所以使用者自己另外裝、剛好一樣的檔案也會被移走；拿新版包裹去移除舊版，則會全部變成 `KEEP`。可以考慮安裝時寫一份清單檔。
- 移除時不會提醒「區塊內容和安裝時不同」。使用者如果在區塊裡改了東西，會被拿掉，只剩備份。

## 安全性逐項

- 沒有 `Remove-Item`。所有覆蓋都會先檢查 `NEW`／`SAME`／`CONFLICT`，有衝突就一個都不複製。規則檔先備份，用嚴格 UTF-8 讀；不是 UTF-8 就 `STOP`。PowerShell 5.1 的預設編碼不會碰到使用者檔案：讀用 `ReadAllBytes`，寫用 `WriteAllBytes`，只有第 4 步自我檢查用 `Get-Content -Encoding UTF8`，而且只讀不寫。
- 不需要系統管理員權限。路徑一律用環境變數或 `-LiteralPath`。`'` 和 `[` 出現在家目錄名稱裡都實測可以。OneDrive 不會改到 `USERPROFILE`。
- 會從網路下載的只有 3A 的 `anthropics/claude-plugins-official` 和 `mattpocock-skills`。Matt 的 README（`離線副本/mattpocock-skills/README.md:35`）只寫 `install`，前面要先 `marketplace add`，這點是作者在沙盒實測補的（證據 16 §2），不是 README 的原文。我沒有重新驗證。
