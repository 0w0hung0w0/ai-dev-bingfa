## Should-fix

**S1. Python 太舊（Python 2，或 3.6 以前）時，檢查會安靜地失效，也不會出現「這項沒啟用」提示**
- 位置：`外掛/dev-bingfa-check/hooks/run.sh:11-13`、`run.cmd:10-12`（找 Python 時只跑 `-c "import sys"`）；`post_check.py:21`、`check_silence.py:35` 都用了 `from __future__ import annotations`（需要 3.7 以上）。
- 重現：`adv.py` 的 J 案例。放一個假 `python`：`-c` 探測回 0，正式執行時印 SyntaxError、回 1。sh／PowerShell／cmd 三條路線結果都是 post=0（不提醒）、session=0 而且**沒有提示**。
- 違反卡 05「不能靜悄悄失效」。
- 修法：三處探測改成 `-c "import sys; sys.exit(0 if sys.version_info >= (3, 8) else 1)"`（`run.cmd` 裡注意引號）。這樣舊版 Python 會被當成「沒有 Python」，開對話時就會顯示提示。

**S2. 一次修補很多檔案時會超過 10 秒逾時（Codex）**
- 位置：`post_check.py:69-72`。每個檔案都另外開一個 Python 程序，`.md`、`.txt` 也開。
- 重現：`adv.py` 的 F 案例。一個修補裡有 300 個 `.md`，跑了 **12.6 秒**，超過 `hooks.json` 的 `"timeout": 10`。60 個 `.py` 跑 2.7 到 3.3 秒。
- 修法：開程序之前先篩選，只留副檔名是 `.py`、而且不是測試檔的路徑（和 `check_silence.py:44-47` 的判準相同）。更好的做法是 `import check_silence`，在同一個程序裡呼叫 `main()`。不必修改 `check_silence.py`，改 `sys.stdin` 就行。

**S3. 兩個網路搜尋助手的「找不到就搜」備案搜尋樣式，對不到真正的安裝位置**
- 位置：`外掛/dev-bingfa/agents/web-search-agent.md:28`、`codex/agents/bingfa-web-search-agent.toml:26`。兩處都寫 `**/dev-bingfa/web-search-modules/*.md`。

- Codex 版的主要寫法已經可以應付版本變動：它寫了 `<version>` 子資料夾、有多個就取最高版本，也照顧到 `CODEX_HOME`，到 v1.1 不會壞。真正的弱點只有這個備案樣式。

4. `hooks.json:8,21` 的 sh 那半段直接叫 `sh`。用 Git `bin\bash.exe` 時正常；直接跑 `usr\bin\sh.exe`、PATH 又沒有 `/usr/bin` 時會 127（非阻擋，但不會出現提示）。另外，PowerShell 那半段只靠 `${CLAUDE_PLUGIN_ROOT}` 的文字替換：沒有被替換時，`poly.py` 顯示結果是 exit 0、沒有任何提示。可以考慮改成 `$env:CLAUDE_PLUGIN_ROOT` 當備案，結束碼保持不變。
5. `post_check.py:67` 遇到前面有 UTF-8 BOM 的輸入會回 0，不檢查（`adv.py` 的 H 案例）。改用 `"utf-8-sig"` 解碼。兩個工具大概都不會送 BOM。
6. `codex/README.md:23,26` 把 `1.0.0` 寫死在給人看的路徑裡。改成 `<版本>/`（例如 `1.0.0`）。
7. `規則/CLAUDE專用附錄.md:7` 寫「most likely `dev-bingfa:explorer`」。`claude plugin validate` 已經顯示 `agents: dev-bingfa:explorer`，可以改成「validate 輸出顯示為…；實際派工時的叫法未實測」。
