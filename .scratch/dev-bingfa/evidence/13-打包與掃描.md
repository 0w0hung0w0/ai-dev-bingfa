日期：2026-11-25。工具都用 Python 寫（只用內建功能），沒有新增 PowerShell 腳本檔。

## 一句話結論

- 掃描：我們自己的檔案**零筆需要處理的問題**。找到的東西都看過，每一筆都寫了理由（見下表）。
- 打包：產出 `dist/dev-bingfa-1.0.zip`，520,623 位元組（約 508 KB），242 個檔案。**壓縮檔裡沒有最上層資料夾**，原因見第 2 節。
- 連打兩次，壓縮檔指紋完全一樣：`a94cd32b1c1d5a46b7065284e495884296b62970ce984f6f5f1f16a6415cf3e2`。
- 用三種方式解壓（Python、Windows 的 `Expand-Archive`、檔案總管用的同一套解壓功能），242 個檔案每一個都和原檔一模一樣。
- 直接用**解壓出來的那一份**跑安裝步驟（在假的使用者資料夾裡）：Claude 版三個外掛都是「enabled」，Codex 版 35 項都複製到位。

### 為什麼壓縮檔裡沒有最上層資料夾（負責人的決定）

同事會在壓縮檔上按右鍵、選「解壓縮全部」。Windows 預設會建立一個和壓縮檔同名的資料夾 `dev-bingfa-1.0\`，再把內容放進去。
- 壓縮檔裡**沒有**最上層資料夾：解出來就是 `…\dev-bingfa-1.0\安裝指示-ClaudeCode.md`，和說明書 1 的 `C:\dev-bingfa-1.0\…` 句子一致。
- 壓縮檔裡如果**有**最上層資料夾（第一版就是這樣）：會變成 `dev-bingfa-1.0\dev-bingfa-1.0\…` 兩層，同事照說明書找不到檔案。

新舊版可以並排放（規格第 7 節）這點不受影響：每一版的壓縮檔名稱帶版本號，解出來的資料夾自然也帶版本號。

### 其他做法

- 中文檔名用 UTF-8 存，並打上「UTF-8 檔名」標記（所有含中文的檔名都有）。
- 每個檔案的時間固定為 2026-01-01 00:00，照路徑排序，內容原封不動放進去（不轉換換行）。
- 打包的是**工作中的檔案**，不是 git 裡的版本。目前三份說明書、`更新紀錄.md`、`包裹地圖.md` 都還沒提交（提交暫停中）。

### 打兩次一樣嗎

改成「沒有最上層資料夾」之後連跑兩次，兩次指紋都是 `a94cd32b…f3e2`。

改版之前也做過一個測試：故意把 `VERSION` 的修改時間改成現在，再打一次，指紋不變（之後已改回原本的時間）。也就是說，檔案的修改時間不會影響壓縮檔。

## 3. 解壓核對

解到 `.scratch/dev-bingfa/research/sandbox/card13/` 底下，資料夾名字都有空白和中文：

| 解壓方式 | 位置 | 檔案數 | 少的 | 多的 | 內容不同的 |
|---|---|---|---|---|---|
| Python `zipfile` | `解壓 測試 python\dev-bingfa-1.0` | 242 | 0 | 0 | 0 |
| Windows 的 `Expand-Archive`（沒有被防毒擋） | `解壓 測試\dev-bingfa-1.0` | 242 | 0 | 0 | 0 |
| 模擬檔案總管預設：壓縮檔放在 `下載 測試\`，目的地是同名資料夾，用檔案總管背後的解壓功能（Shell）解 | `下載 測試\dev-bingfa-1.0` | 242 | 0 | 0 | 0 |

- 三種方式解出來，`安裝指示-ClaudeCode.md` 都**直接在** `dev-bingfa-1.0\` 裡面，沒有多一層。
- 「內容不同」是逐檔比對指紋。Matt 離線副本的 187 個檔案也全部一模一樣。
- `.sh` 都是 LF 換行、`.cmd` 都是 CRLF 換行（解壓後再查一次）。
- 這些都在：三份說明書、四份給 AI 讀的指示（安裝 Claude、安裝 Codex、移除、貼指令備案）、`更新紀錄.md`、`VERSION`、`包裹地圖.md`。
- 把解出來的內容複製成 `檢查根\dev-bingfa` 再跑檢查：`check_package.py --root` 13 項全部通過（包括 98 個存檔檢查情境），`scan_package.py --root` 0 筆。
